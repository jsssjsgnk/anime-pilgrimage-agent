# 数据、版权与安全边界

## 数据来源

- Bangumi：保存 Subject ID、来源和查询时间；遵守 User-Agent 建议；MVP 只读；
- 巡礼点：不编造；不批量重新分发第三方图片或完整数据；保留 provider/source/fetched_at；
- 攻略：优先官方公告、场所官网和旅游机构；社区经验不能覆盖官方规定；
- SearchAPI：航班价格显示查询时间和需再次确认；
- ORS/地图：计划估算与现场导航明确区分；
- 用户上传：独立命名空间，限制类型/大小，不公开再分发。

## RAG 来源优先级

```text
官方公告与场所规定
> 场所官网
> 地方政府/旅游协会
> 结构化点位说明
> 可信社区攻略
> 普通用户笔记
```

保存摘要、元数据、原链接和访问日期，不重新发布完整社区笔记和图片。来源冲突时显示冲突，不由 LLM 静默裁决。

## 密钥

- 真实值只在本机 `.env` 或部署 secret store；
- `.env` 在 `.gitignore`，`.env.example` 为空；
- 前端 bundle、URL、日志、异常、报告、截图、Fixture 均不得出现密钥；
- 对 Authorization、Cookie、token、key、MCP signed URL 统一脱敏；
- 错误只说缺少哪个变量，不回显值。

## MCP 和 Agent

- MCP 服务仅内部网络、只读、工具白名单、最小权限；
- 禁止 runtime Agent 使用 shell、任意文件、任意 URL 或数据库原始查询；
- 外部工具描述和结果视为不可信；
- 付款、出票、预订、证件和写操作不在工具集中；
- Agent 无权读取技术日志、其他 thread、其他 trip 或其他用户数据。

## Anitabi 决策

Codex 必须先检查公开规则。没有稳定且允许的接口时，不实现绕过方案，而是交付导入 Provider、Fixture、来源说明和已知限制。这种合规降级视为正确实现，不是失败。

## 最终提醒

UI 和导出必须提示用户出发前重新确认航班价格、营业时间、天气、交通、访问和拍摄规定。
