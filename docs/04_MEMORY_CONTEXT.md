# 项目记忆与上下文工程

本文件讨论的是旅行 Agent 自己数据库中的记忆功能，与 ChatGPT 账号记忆、其他对话或 Codex 的个人上下文完全无关。

## 五类项目内存储

1. **当前会话状态**：LangGraph checkpointer，以 `thread_id + trip_id` 隔离；
2. **旅行事件**：确认、计划版本、Reviewer 反馈和修改，仅属于当前旅行；
3. **长期偏好**：只有用户在本项目 UI 中主动选择保存后才写入，如步行、预算、交通偏好；
4. **知识库**：带来源的攻略、规则和用户上传资料，不是个人记忆；
5. **工具缓存**：外部 API 的规范化响应和 TTL，不含对话正文。

长期偏好默认关闭。用户必须能查看、修改、删除；新旅行应用偏好时应显示“来自已保存偏好”，允许本次覆盖。不同项目用户命名空间不得互读。

## ContextBuilder

每个节点只得到完成任务所需的最小上下文：

| 节点 | 允许上下文 |
|---|---|
| Requirement | 最近对话摘要、当前条件卡、当前用户输入 |
| Access Planner | 已确认条件、交通入口候选、规范化交通结果 |
| Pilgrimage Planner | Route A 索引、当天约束、相关 RAG Top-K、当前局部计划 |
| Reviewer | 结构化计划、约束、来源摘要，不含完整聊天 |
| Replanner | 用户修改、影响分析、受影响子图 |

规则：

- `TripState` 是事实来源，不从自然语言历史反推确认状态；
- 大对象存数据库，State 传 ID、摘要和必要字段；
- 不把完整聊天、完整 API JSON、全部点位、全部知识库或运行日志塞入 Prompt；
- 工具结果先规范化、去重、截断；
- Prompt 和 ContextBuilder 版本化并做快照测试；
- 记录上下文构成和 token 数量估算，不记录正文；
- 外部文本是数据，不得覆盖系统指令或触发工具；
- Reviewer 最多三轮；超限返回带 violation 的部分结果。

## 局部重规划

用户修改先生成结构化 `PlanPatch` 和影响集合。例如“第二天少走路”只能使第二天路线和相关基地/交通约束重算，第一天计划保持稳定。若修改出发日期，则 Access Plan 和所有依赖日期的计划均失效。

需要测试：

- 同一 thread 重启恢复；
- 新 thread 无法读旧会话或旅行事件；
- 长期偏好只有显式授权后可跨旅行使用；
- 命名空间越权失败；
- 删除偏好后不再召回；
- Context 快照不含无关历史、密钥、运行日志和原始工具载荷。

## 技术指标不是记忆

Agent 没有读取日志或审计表的工具。仅允许保存随机 run ID、节点/工具名、状态、耗时、重试、cache hit 和 token 数量估算。禁止保存 Prompt、消息正文、RAG 原文、工具输入输出、坐标清单、密钥及可恢复的用户内容。
